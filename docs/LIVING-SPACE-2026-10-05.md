# 활동 공간: 기본 바닥 / 화면 전체

## 사용자 의도와 적용 방식
- 기본은 화면 아래쪽의 수평 바닥에서 생활한다. 별도 불투명 방 창을 만들지 않는다.
- 동물 우클릭 → 꾸미기 → 가구 배치 → 활동 공간에서 `아래쪽 바닥 (기본)` / `화면 전체`를 선택한다.
- 같은 꾸미기 메뉴의 `화면 전체로 넓히기` 항목으로도 전환한다.
- 가구에 동물을 끌어 놓아 사용하기는 두 모드에서 유지한다.

## 구현
- `living_space.gd`가 발의 이동 범위를 계산한다. 바닥은 작업 표시줄 위, 기존 화면 안전 여백 안의 1px 수평 구간이다. 점프와 앉기 같은 그림의 높이 변화는 그대로 둔다.
- 마우스로 잡은 동안에는 커서 위치를 그대로 따라간다. 바닥 밖에 짧게 놓으면 내려와 착지한다. 3초 이상 잡았다 놓을 때는 기존 낙하·해롱 동작을 유지한다. 버둥거림 시작은 기존 2초이다.
- 렌더링용 투명 창의 크기는 바꾸지 않는다. 모드 때문에 창 크기나 캐릭터 크기가 반복 변경되지 않는다.
- 가구와 소품은 바닥 모드에서 하단에 정렬된다. 가구는 그림의 94% 높이를 접지 기준으로 사용한다.
- 기존 저장의 세로 배치는 보존한다. 바닥 모드에서 가로 위치를 바꾸면 가로 위치는 저장하되, 화면 전체로 돌아갈 때 기존 세로 위치를 복원한다. 새 가구에는 생성 시 위치가 기준이 된다.
- 일반 저장에 `activity_space`를 추가했다(version 6). 누락/잘못된 값은 `floor`이다.
- 점검판은 `interior-layout.json`의 기존 가구 딕셔너리를 읽고, 이후 `{version:2, furniture, activity_space}`로 저장한다. 성장/해금 진행 데이터는 변경하지 않는다.
- 동물을 다른 모니터로 옮기면 그 모니터의 바닥을 사용한다. 가구 자동 정렬은 기본 모니터 기준이며, 전체 모드에서는 기존 자유 배치가 가능하다.

## 검증
- `tests/living_space_test.gd`: 16종 × 새끼/성체 × 화면 좌표 3종(음수 원점 포함), 좌우 이동의 바닥 이탈 검사, 짧은/긴 낙하, 모드 전환, 가구 원래 높이 복원, 설정 실제 저장/재로드 통과.
- `tests/furniture_drop_test.gd`: 기존 640개 끌어 놓기 경로 통과.
- `tests/tool_delivery_test.gd`: 순차 도구 도착과 방문 통과.
- `tests/living_space_native_review.gd`: 사용자 저장을 수정하지 않는 실제 Windows 게임 실행. Computer Use로 공간 선택을 `바닥 → 화면 전체 → 바닥` 변경하고 화면 및 내부 범위 변경 확인. 바닥에서 소파 접근 후 `home_use` 진입 확인. 실행 오류 로그 비어 있음.
- 이번 검증은 공간 설정과 해당 상호작용에 대한 것이며 모든 종의 모든 애니메이션 미술 검수를 다시 수행한 것은 아니다.

## 유지보수
- 모니터 갱신과 드래그 중 모니터 변경도 반드시 `activity_bounds`를 거친다. 전체 화면 범위로 직접 덮어쓰면 바닥 모드가 풀린다.
- 바닥 범위 높이를 0으로 만들면 `Rect2.has_point` 및 경계 검사가 실패한다.
- 도구 배달 위치 계산 시 바닥 모드의 세로 안쪽 여백은 0이어야 한다.
- 코드만 바꾼 패키지는 `tools/package.gd --reuse-assets-from=<검증된 기존 PCK>`로 기존 그림을 재사용할 수 있다. 그림이 바뀐 작업에서는 사용하지 않는다.
