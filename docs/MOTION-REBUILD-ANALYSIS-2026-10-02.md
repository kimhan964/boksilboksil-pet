# 움직임 재분석·재제작 설계

## 사용자 최종 제작 지시 — 시범 검토 후

사용자가 리깅 시범을 품질 부족으로 거절했다. **전신 이미지 프레임 방식으로 더 정교하게 제작한다.** 아래 리깅 추천은 이전 분석 기록이며 현재 실행 기준에서 제외한다. 새 시범은 `design/rabbit-frame-pilot-v2`에 저장하고 완성된 전신 프레임을 그대로 재생한다. 거절된 시범은 `design/rabbit-pilot-v1-rejected`에 보관했다.

2026-10-02 사용자 실제 플레이 피드백: 움직임이 너무 빠르고 어색함. 현재 버전은 자연스러움 승인 보류 상태다. 이 문서는 분석과 제안이며, 아래 새 속도·새 제작 방식이 설치 게임에 적용됐다는 뜻은 아니다.

## 1. 확인 근거

- 설치된 DesktopFriends.exe의 실제 창과 연못 클릭 후 이동·행동 전환을 확인했다.
- `build_walk_v4.cjs`, `generated_species_art.gd`, `character_presentation.gd`, `desktop_pet_motion.gd`, `desktop_pet_view.gd`를 함께 추적했다.
- 16종 새끼·성체의 기존 16장과 현재 32장을 비교했다. 진단 결과는 `design/motion-reanalysis-2026-10-02/walk-consistency.json`이다.
- 현재 32장은 기존 전신 16장과 별도로 생성한 전신 16장을 번갈아 재생한다. 같은 애니메이션 곡선의 정확한 중간 시각을 렌더한 자료라는 보장은 없다.
- 실루엣 겹침의 중앙값은 32개 단계 중 31개에서 16장보다 개선됐다. 따라서 '프레임을 늘려서 모두 더 나빠졌다'는 판정은 맞지 않는다. 다만 이 수치는 발 접지, 같은 발의 궤적, 체중 이동, 표정 연속성을 평가하지 못한다.
- 현재 보정의 중간 프레임 가로·세로 배율 비율은 전체 단계에서 약 0.949~1.054다. 토끼 성체는 약 0.991~1.016, 새끼는 0.985~1.030이다. 이 수치만으로 모든 어색함의 원인이라고 단정할 수 없지만 프레임별 형태를 바꾸는 표시 방식은 새 제작에서 제거할 대상이다.

## 2. 문제와 원인

### A. 그림을 늘렸지만 동작의 중간 자세를 통제하지 않았다

현재 중간 프레임 제작은 별도 생성 시트를 기존 그림 사이에 넣는다. 실제로 어느 발이 지지 중인지, 지지발은 얼마나 뒤로 움직여야 하는지, 머리·귀·꼬리의 지연은 얼마인지에 대한 궤적과 접지 표시가 없다. 생성한 결과를 시간순으로 묶었다고 정확한 걸음이 되지는 않는다.

원화 모델은 대표 디자인·장식·색을 만드는 보조 수단으로 사용한다. 최종 걷기는 한 모델과 한 동작 곡선에서 연속된 자세를 제작하거나, 지정된 전신 키포즈와 중간 자세를 직접 통제해야 한다.

### B. 크기 보정이 체중 이동까지 건드린다

현재 걷기는 매 프레임의 투명 영역을 제외한 그림 높이를 중립 높이에 맞춘다. 귀가 내려가거나 무릎을 굽혀 전체 높이가 줄어든 자세도 확대된다. 발바닥 기준을 매번 그림의 최하단으로 옮기므로, 실제 지지발의 기준과도 다를 수 있다. 중간 프레임은 가로 배율까지 별도로 보정한다.

새 제작은 종·성장 단계마다 고정 카메라와 고정 배율을 사용한다. 같은 캐릭터 크기는 머리·몸의 기준 형태로 검수하고, 동작에 따른 무릎 굽힘·귀 움직임·착지 눌림은 허용한다. 그림 외곽의 높이가 항상 같아야 한다는 검사는 폐기한다.

### C. 이동 경로와 실제 발 움직임의 연결이 부족하다

일반 걷기는 실제 이동 거리로 walk_phase를 진행하므로 완전히 독립된 재생은 아니다. 그러나 한 주기 이동 거리 자체를 속도×기본 주기로 정하며, 원화의 지지발 이동을 측정해 정한 값은 아니다. 지지발이 화면 좌표에서 멈추는 보장은 없다. signature 행동은 시간에 따른 위치 보간을 별도로 사용한다.

새 제작에서는 '접지 중인 발의 월드 위치가 유지된다'는 기준으로 보폭과 화면 이동을 맞춘다. 걸음 중간에 순간 속도가 바뀌어도 발 접지와 몸의 이동을 함께 계산한다. 별도의 특수 이동 경로에도 같은 원칙을 적용한다.

### D. 템포가 급하고 전환이 짧다

토끼의 정상 성체 이동은 약 66px/초, 걷기 한 주기는 약 1.05초다. 가속 목표 시간은 0.24초이고 공 추격·복귀는 1.5배 속도로 이동한다. 도착 직후에는 현재 걸음의 접지 여부와 무관하게 다음 상태로 넘어간다.

새 시범값은 아래와 같다. 이는 제안값이며 실제 플레이 비교로 확정한다.

| 항목 | 현재 | 새 시범 목표 |
|---|---|---|
| 토끼 일반 이동 | 약 66px/초 | 35~45px/초 |
| 토끼 걷기 한 주기 | 약 1.05초 | 1.5~1.8초 |
| 출발 가속 목표 시간 | 0.24초 | 0.5~0.7초 |
| 공 추격·복귀 | 약 99px/초 | 50~60px/초, 별도 빠른 걸음 |
| 이동 뒤 쉬기 | 약 0.7~1.8초 | 약 1.5~3초 |

속도와 주기를 따로 바꿔 발이 미끄러지게 하지 않는다. 약 70px의 보폭이라면 44px/초와 약 1.6초 주기가 대응한다. 위 값의 조합도 실제 원화의 보폭을 확인한 뒤 고른다. 전체 게임 시간을 늦추거나 화면 표시 FPS를 낮추는 방법은 쓰지 않는다.

### E. 종별 움직임·행동 구조가 덜 구분돼 있다

공통 수치만 바꾸는 방식으로는 토끼의 작은 깡충걸음, 다람쥐의 가벼운 잔걸음, 곰·판다의 느긋한 체중 이동, 펭귄의 좌우 무게 이동을 표현하기 어렵다. 이동과 특수 행동 모두 종에 맞는 키포즈와 박자가 필요하다. 이는 사실적인 생체 동작을 완전히 재현한다는 뜻이 아니라 캐릭터 연출 설계다.

### F. 검사 기준이 자연스러움을 승인하지 못했다

이전 71,168자세 검사와 오류 0은 공백·창 잘림·높이 변화·기능 경계 검사의 결과다. '자연스러운 게임 애니메이션 완성'의 증거가 아니다. 앞으로 기술 검사와 플레이 품질 승인을 별도로 기록한다.

## 3. 제작 방식 비교

| 방식 | 장점 | 비용·위험 | 판단 |
|---|---|---|---|
| 전신 키포즈·중간 그림을 직접 통제하는 2D 프레임 제작 | 큰 자세 변화와 귀여운 실루엣을 세밀하게 표현 | 16종·새끼·성체·의상별 작업량이 큼 | 큰 자세 변화에 사용 |
| 제작용 2D 리깅 후 완성 전신 PNG 출력 | 같은 형태·색을 유지하며 접지·박자·의상을 통제 | 제작 단계의 몸·다리 준비와 가림 순서를 정확히 설계해야 함 | 기본 이동·의상에 추천 |
| 이미지에서 동영상 생성 후 프레임 추출 | 시간상 연속된 결과를 얻을 가능성 | 얼굴 변형, 접지, 루프 경계, 의상 변형은 별도 검수 필요 | 시범 비교용, 바로 양산하지 않음 |
| 현재처럼 독립 생성 그림을 번갈아 끼우기 | 빠르게 프레임 수를 확보 | 동작 궤적과 접지 보장이 없음 | 신규 걷기 제작 경로에서 제외 |

추천은 **통제된 2D 제작용 리깅 + 큰 자세 변화의 전신 키포즈를 함께 사용하고, 게임에는 완성된 전신 프레임으로 내보내는 방식**이다.

제작 단계에서 몸·다리·귀·꼬리 등을 준비해야 한다. 눈·입·얼굴은 한 묶음으로 유지하여 눈 조각이 따로 움직이는 구조를 만들지 않는다. 최종 게임 표시에는 기존처럼 완성 전신 이미지가 들어간다. 리깅만 적용하면 곧바로 귀여워진다는 보장은 없으며, 키포즈·변형 범위·가림 순서를 실제 화면에서 검수해야 한다.

Spine는 발을 목표 위치에 맞추는 IK와 의상별 스킨, PNG 시퀀스 출력을 지원한다. 기능의 근거는 아래 공식 문서다. 특정 제작 프로그램 설치·구매는 이 분석에서 실행하지 않았다.

- [IK·발 위치 제어](https://esotericsoftware.com/spine-ik-constraints)
- [의상 스킨](https://us.esotericsoftware.com/spine-skins)
- [PNG 시퀀스 출력](https://esotericsoftware.com/spine-export)
- [Godot 프레임 재생 속도·개별 유지 시간](https://docs.godotengine.org/en/stable/classes/class_spriteframes.html)

## 4. 새 제작 순서

1. **토끼 새끼·성체 두 모델부터** 기존 귀여운 대표 디자인·색·눈 간격·머리 비율을 고정한다. 현재의 잘못된 움직임 그림을 동작 기준으로 삼지 않는다.
2. 정면에 가까운 현재 시점에서 걷기 접지→몸 내려감→발 통과→몸 올라감의 전신 키포즈를 설계한다. 토끼의 짧은 깡충 연출도 비교 후보로 만든다.
3. 얼굴 한 묶음, 몸·지지발·들리는 발·귀·꼬리의 동작 관계를 만든다. 지지발은 월드 위치를 유지하고 귀·꼬리는 몸보다 조금 늦게 움직인다.
4. 정지→출발 준비→걷기 시작→걷기 반복→마지막 접지→정지로 상태를 구분한다. 잠에서 깨며 이동할 때도 일어나는 동작을 끝낸 뒤 걸음을 시작한다.
5. 기본 배율을 고정하고 접지·입·손·의상 위치를 제작 데이터에 명시한다. 외곽 높이로 매 프레임 전신을 늘이거나 누르지 않는다.
6. 동일한 동작에서 32~48개 전신 프레임을 출력한다. 출력 프레임 수·행동 길이·화면 표시 FPS를 분리한다. 한 주기 1.6초에 32프레임이면 그림 교체는 약 20회/초이며, 위치 이동·화면 표시는 60회/초로 유지할 수 있다.
7. **실제 게임 크기에서 20초 이상**, 배경·음식·연못과 함께 재생해 이전 버전과 비교한다. 확대 영상·정지 비교표만으로 승인하지 않는다.
8. 토끼 새끼·성체의 기본 이동이 승인되면 표정·먹기·마시기·잠·들기·점프·낙하·해롱해롱을 새 구조에 맞춘다.
9. 옷은 제작용 몸 위치에 연결하여 같은 애니메이션으로 출력한다. 자세와 무관한 서 있는 옷 이미지를 그대로 겹치는 방식은 새 시범에서 사용하지 않는다.
10. 토끼 기본·의상·단계 전환이 통과한 뒤 체형별로 나머지 종에 적용한다. 긴 귀, 긴 꼬리, 둥근 몸, 짧은 다리를 같은 리깅 설정으로 무작정 복제하지 않는다.

## 5. 행동별 검수 기준

| 행동 | 새 검수 기준 |
|---|---|
| 기본·걷기 | 얼굴·머리 기본 형태 유지, 지지발 미끄러짐 확인, 좌우 체중 이동과 접지 박자 일치 |
| 출발·멈춤·방향 전환 | 바로 반대로 움직이거나 공중 자세에서 정지하지 않음. 몸 돌림·마지막 접지 확인 |
| 먹기 | 손·음식·입의 접촉 위치와 씹는 박자 일치 |
| 연못 마시기 | 입이 수면에 접근해 유지되고 몸 전체가 반복해서 늘어나지 않음 |
| 수면·휴식 | 눕기·호흡·일어나기의 구간을 명시하고 잠든 루프에 일어나는 그림이 섞이지 않음 |
| 표정 | 준비→표정→유지→복귀의 전신 움직임, 얼굴 크기 유지 |
| 들기·놓기 | 들린 몸의 긴장·다리 반응. 기존 3초 낙하 기준 유지 |
| 점프·낙하 | 준비·도약·정점·착지 구분. 캐릭터 몸 이동과 창의 이동 관계 확인 |
| 의상 | 몸의 가림 순서·머리/귀 보호·잠/걷기/들기 중 부착 위치와 색 유지 |

## 6. 새 승인 기준

- 고정 배율·고정 모델로 재생한다. 머리·몸의 기본 형태를 검사하고 귀와 무릎의 정상 자세 변화는 허용한다.
- 지지발을 제작 데이터로 지정하고, 접지 구간의 월드 위치 오차는 실제 화면 기준 약 1~2px 이내를 시범 목표로 한다.
- 루프 경계의 자세·속도·의상 위치가 연속적이어야 한다. 같은 그림을 중복해서 넣어 경계를 멈추게 만들지 않는다.
- 기본·의상·새끼·성체 전환에서 걸음 주기와 현재 접지 위상을 유지한다.
- 같은 동작을 30·60·144Hz에서 비교하고 도착·속도·발 접지가 달라지는지 확인한다.
- 수치 통과 후 실제 게임에서 귀여움·자연스러움·눈 피로를 다시 승인한다. 동물 16종에 확대하기 전 토끼 시범 품질을 먼저 확정한다.

## 현재 상태

분석과 기존 데이터 진단만 완료했다. 설치 게임의 속도·원화·표시 방식은 이 분석 중 변경하지 않았다. 새 제작은 토끼 새끼·성체의 실제 걷기 비교 시범을 첫 산출물로 삼는다.
