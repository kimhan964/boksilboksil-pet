## 2026-10-01 · 높은 낙하·귀여운 효과·마우스 조작·소품 간소화

## 2026-10-01 · 걷기 32프레임, 놓기 후 해롱해롱, 해금 선물 연출

- 걷기의 기준은 기존 승인된 4×4 원본 16장이다. 토끼 새끼·성체를 먼저 시범으로 만들고 크기·색·발 위치를 검수한 뒤, VARCO MCP에서 16종의 새끼·성체별 **사이 자세 16장**을 별도로 생성했다. 승인 원본과 사이 자세를 번갈아 배치해 단계마다 32장의 완성형 전신 이미지를 사용한다. 파츠 분리와 두 이미지의 교차 페이드는 사용하지 않는다. 생성 노드·출력 URL은 `design/walk-v4/varco-nodes.json`에, 원본은 `design/walk-v4/raw`, 게임용은 `assets/walk-v4/{species}/{baby,adult}.png`에 둔다.
- `tools/build_walk_v4.cjs`는 청록 배경 제거와 한 시트 공통 배율, 발 원점 정렬, 가장자리 검사 후 8192×256 스트립을 만든다. `design/walk-v4/review/all-1.png`부터 `all-4.png`에서 16종의 새끼·성체 중간 자세를 비교했다. `tests/walk_v4_test.gd`는 전신 1,024장, 잘림·빈 칸, 30/60/144fps 이동 48건을 검사한다.
- `scripts/desktop_pet_motion.gd`는 이동한 실제 거리에 따라 걷기 위상을 진행한다. 예전 발 접지용 속도 진동은 이동을 끊겨 보이게 하므로 제거했고, `scripts/gait_profile.gd`에서 종별 걸음 주기를 짧게 맞췄다. `scripts/desktop_pet_view.gd`는 첫 발걸음 전에 걷기 텍스처와 클릭 윤곽을 준비한다. 기본 복장 없는 동물은 32프레임을 사용한다. 기존 전신 의상 걷기 시트가 있는 기본색 의상은 의상이 몸에 정확히 붙도록 기존 16프레임을 유지한다. 의상 애니메이션 확장 절의 미완료 조건은 그대로 적용된다.
- 드래그해 놓으면 착지 후 해롱해롱 자세가 나오며, 이전에 소품으로 이동 중이었다면 회복 뒤 그 방문을 이어 간다. VARCO에서 16종 × 새끼·성체 × 4자세 = 전신 그림 128장을 생성했다. 노드·출력은 `design/dizzy-v1/varco-nodes.json`, 원본은 `design/dizzy-v1/raw`, 게임용은 `assets/dizzy-v1/{species}/{baby,adult}.png`다. `tests/emotion_toy_test.gd`가 전 그림을 검사한다.
- 친밀도에 따른 소품 해금에서는 새 소품 창이 화면 위에서 떨어져 한 번 튀고, 착지 후 동물이 방문 순서에 넣어 살펴보거나 쉰다. 이동 중인 소품은 일반 방문 대상으로 노출하지 않고, 저장 좌표는 착지 위치를 사용한다. `tests/unlock_fall_test.gd`에서 시작·착지·방문 대기 상태를 검사한다. 게임 재실행 때 이미 해금된 소품은 다시 떨어지지 않는다.
- 재작업 순서: 대표 원화와 현재 걷기 16장 확인 → 토끼 새끼·성체 사이 자세 생성 → 원본과 나란히 색·실루엣·발 위치 검수 → 나머지 종 생성 → `build_walk_v4.cjs` 실행 → 4장 비교표 검수 → `walk_v4_test.gd` → 실제 게임과 패키지 실행 확인. 프레임 수만 늘리고 화면 이동과 보폭을 맞추지 않으면 스케이트처럼 보여 통과로 처리하지 않는다.

## 1. 최우선 제작 원칙

1. 2D 완성형 전신 이미지만 사용한다. 3D, 파츠 분리, 본 리깅, 눈·귀·몸 조립은 금지한다.
2. 새끼와 성체는 별도 원화를 사용한다. 성장 차이는 머리·몸·팔다리 비율로 표현한다.
3. 같은 종의 새끼와 성체는 털색, 무늬색, 볼·귀 안쪽 색, 목 장식 색, 외곽선, 광원, 명암 단계를 동일하게 유지한다.
4. 대표 원화가 승인되기 전에 행동 시트를 대량 생성하거나 게임에 연결하지 않는다.
5. 각 단계는 산출물, 비교표, 정량 기록을 남기고 합격한 경우에만 다음 단계로 넘어간다.
6. 사용량 절약보다 품질과 일관성을 우선한다. 불합격 결과는 다음 단계에서 보정하지 않고 해당 단계에서 고친다.
7. 모든 행동은 4열×4행의 16개 완성 전신 프레임으로 제작한다. 프레임 복제나 단순 교차 페이드는 프레임 증가로 인정하지 않는다.
8. 귀여움 기준은 종 특성보다 먼저 실루엣에서 확인한다. 머리는 전체 높이의 45~50%, 몸통은 넓고 짧게, 다리는 전체 높이의 18% 이하를 기본값으로 삼고 종 특성상 필요한 경우만 예외를 기록한다.

## 2. 단계별 통과 절차

### 0단계 · 기존 자료 잠금

- 기존 이미지, 프롬프트, 모델, 노드 ID, 생성 날짜를 보존한다.

통과 조건: 원본과 새 결과의 경로가 분리되고 덮어쓰지 않는다.

### 1단계 · 대표 원화 쌍 제작

종마다 새끼 대표와 성체 대표 두 장만 먼저 만든다. 새끼는 큰 머리와 눈, 짧고 통통한 몸, 짧은 팔다리를 사용한다. 성체는 같은 정체성과 팔레트를 유지하고 성체에 맞는 몸통과 팔다리 비율을 사용한다.

대표 원화에서 고정할 항목:

- 종, 얼굴 윤곽, 눈 수와 위치, 귀·꼬리·무늬.
- 털 기본색과 그림자색.
- 귀 안쪽, 볼, 배·주둥이, 발끝 색.
- 목 장식의 종류와 색.
- 짙은 갈색 외곽선과 내부선 굵기.
- 우상단 광원, 2단 셀 채색, 같은 카메라 거리와 3/4 시점.

산출물:

- design/all-species-v3/masters/{species}/baby.png
- design/all-species-v3/masters/{species}/adult.png
- design/all-species-v3/masters/representative-review.png
- design/all-species-v3/masters/character-spec.json

통과 조건:

- 육안: 두 단계가 같은 캐릭터로 보이며 성장 비율만 달라진다.
- 색상: 주요 팔레트의 가중 CIE Lab 평균 색차가 목표 ΔE 3 이하이고, 명백한 종 변경이나 색상 계열 변경은 0건이다. 작은 눈 반사광처럼 성장 단계에서 면적이 달라지는 색은 최대값 진단에는 남기되 단독 불합격 사유로 쓰지 않는다.
- 형태: 눈·귀·팔다리 누락, 다른 종 혼입, 잘림, 배경 오염이 0건이다.
- 비교표에 approved: true가 기록된 종만 다음 단계로 이동한다.

### 2단계 · 시범 모션 3종

대표 원화를 직접 참조해 단계별로 대기, 걷기, 쓰다듬기만 생성한다.

통과 조건:

- 첫·마지막 중립 자세가 대표 원화와 같은 얼굴·색·몸 크기를 유지한다.
- 한 행동 안에서 프레임마다 털색과 명암이 변하지 않는다.
- 발 접지, 눈 두 개, 귀·꼬리·팔다리 연결이 자연스럽다.
- 256×256 공통 캔버스에서 잘림이 없고, 행동마다 몸이 재확대되지 않는다.
- 걷기 16프레임에는 접지, 밀기, 통과, 들기 자세가 좌우 발에 각각 존재한다.
- 접지 중인 발은 연속 프레임에서 화면 이동 방향의 반대로 이동하며 바닥 높이를 유지한다. 몸통은 보폭에 맞춰 상하 이동과 좌우 체중 이동을 보인다.
- 게임 이동 거리와 한 걸음 주기를 함께 재생해 발이 미끄러져 보이지 않는지 확인한다. 정지 시 중립 자세로 자연스럽게 수렴한다.

### 3단계 · 나머지 행동 확장

2단계 통과 후에만 먹기, 마시기, 수면, 들기, 점프, 바라보기, 킁킁, 인사, 몸단장, 기지개, 부비기, 장난감, 휴식을 만든다.

- 항상 승인된 대표 원화를 직접 참조한다.
- 직전 행동 결과를 다음 행동의 기준 원화로 사용하지 않는다.
- 4열×4행, 16개의 완전한 전신 프레임을 사용한다.
- 빈 칸이나 불량 프레임은 이미지 생성 단계에서 다시 만든다. 인접 프레임 복제로 제작 완료 처리하지 않는다.

통과 조건: 종별 16행동×2단계의 행동 비교표에서 색·형태·잘림 오류가 없다.

### 4단계 · 게임용 후처리

허용:

- 시안 배경 제거와 알파 정리.
- 연결되지 않은 움직임 표시·잡티 제거.
- 공통 256×256 캔버스 배치.
- 행동 시퀀스 전체에 한 번만 적용하는 배율 보정.
- 발 원점, 입, 손 좌표 기록.
- 대표 원화 팔레트에 맞춘 시퀀스 단위 색 보정.

금지:

- 프레임마다 키를 200px로 강제 확대.
- 눈·머리·몸·귀·팔다리 분리와 재조립.
- 긴 교차 페이드로 중간 자세 대체.
- 다른 성장 단계나 다른 종의 프레임 재사용.

통과 조건: 같은 단계의 행동 전환에서 몸 크기와 발 위치가 튀지 않고, 새끼·성체 팔레트가 대표 원화와 일치한다.

### 5단계 · 게임 통합

- 모든 종은 하나의 완성 프레임 로더를 사용한다.
- 행동 선택만 공통으로 두고 텍스처는 종·성장 단계별 에셋을 읽는다.
- 음식과 장난감은 기록한 손 좌표에 별도 합성한다.
- 직접 먹여주기 판정은 기록한 입 좌표를 사용한다.
- 기존 임시 이미지 분기는 새 경로가 정상일 때만 비활성화한다.

통과 조건: 16종의 새끼·성체가 대기, 이동, 쓰다듬기, 식사, 수면, 들기, 소품 행동에서 새 에셋을 사용한다.

### 6단계 · 설치본 제작과 실행 확인

- 새 버전 폴더에 PCK와 EXE를 만든다.
- 이전 설치본과 저장 파일은 보존한다.
- 대표 비교표, 행동 비교표, 제작 지침을 설치 폴더에 포함한다.
- 새 실행본을 실행해 창 제목, 선택한 동물, 성장 단계, 행동 전환을 확인한다.

## 3. VARCO 노드 운용 규칙

- 모델: gpt-image-2.5-flare.
- 대표 원화 노드와 행동 노드를 분리한다.
- 행동 노드의 sourceImage는 승인된 해당 종·단계 대표 원화만 연결한다.
- run_workflow.scope에는 현재 단계의 노드만 넣는다. 빈 scope로 전체 워크플로를 실행하지 않는다.
- 결과를 받은 즉시 종·단계·행동 경로에 저장하고 노드 ID와 출력 URL을 기록한다.
- 한 종을 대량 생성하기 전에 대표 원화 쌍과 시범 모션 3종을 먼저 검수한다.

## 4. 색·톤 검수 기록

각 종의 character-spec.json에 species, palette_source, outline, fur_base, fur_shadow, muzzle_belly, cheek_inner_ear, accessory, baby_adult_delta_e_max, identity_errors, approved를 기록한다.

자동 색차는 검수 보조 수단이다. 서로 다른 부위가 우연히 비슷한 평균색을 갖는 경우를 막기 위해 대표 비교표를 함께 확인한다.

## 5. 현재 인수인계 상태

- 0.30.0은 자동 검증을 통과했지만 실제 화면 검수에서 성체의 귀여운 실루엣 감소와 걷기 미끄러짐이 확인되어 승인 취소 상태다.
- 수정 대표 원화는 design/all-species-v3/masters에 있다. 예전의 둥근 성체 실루엣과 현재 새끼의 팔레트·무늬·장식을 함께 참조해 다시 제작했다.
- design/all-species-v3/masters/representative-review.png를 육안 검수했고 character-spec.json의 16종 visual_review와 approved가 모두 통과 상태다.
- 강아지는 승인 대표에서 직접 만든 16행동×2단계×16프레임, 총 512개 셀을 먼저 완성하고 검수한 뒤 같은 규격을 나머지 15종에 적용했다.
- 원본의 요청 규격은 4열×4행이지만 실제 생성 결과에는 4열×3행·행마다 다른 열수도 있다. 격자 규격을 가정해서 승인하지 않는다. 런타임은 16셀로 정리하고 프레임 1과 16을 중립 경계로 사용한다. 걷기는 접지·체중 수용·밀기·통과·발 들기·앞으로 뻗기 순서를 양발에 넣는다.
- 16종 모두 assets/species-v3/{species}에 16행동×2단계×16프레임 런타임 에셋과 manifest.json이 있다.
- 0.30.1 범위는 16종×2단계×16행동×16프레임, 총 8,192개 완성 전신 프레임이다.
- 최종 검증 파일은 design/all-species-v3/production-review/validation.json이며 PRODUCTION_CELS=8192 FAILURES=0이다.
- 게임 공통 로더는 scripts/generated_species_art.gd이며 desktop_pet_view.gd의 모든 종 표시가 이 경로를 사용한다.

## 6. 다음 작업자가 바로 할 일

## 7. 2026-10-02 실제 게임 점검 인수인계

- 상세 기록: `docs/GAMEPLAY-REPAIR-CHECKLIST-2026-10-02.md`. 실제 Main과 네이티브 펫·소품 창으로 16종×2단계×22행동 704개를 재생했고, 3의상×기본·걷기·수면 288화면을 추가 검수했다. 기본 걷기는 실제 속도, 다른 행동은 빠른 프레임 검수다.
- 들기는 마우스 누름이 아니라 실제 이동 제스처로 carried가 된 순간부터 잰다. 3초 미만은 이동 배치, 3초 이상은 낙하→착지→4.8초 해롱해롱이다. 사용자 문구와 검사 기준을 함께 유지한다.
- `character_presentation.gd`에서 전신 이미지의 표시 크기·발 기준·걷기 중간 프레임 폭을 보정한다. 누움·숙임은 첫 중립 프레임에 맞춘 고정 배율로 두어 몸이 낮아지는 자세를 보존한다. 해부학적 파츠를 만들지 않는다.
- `desktop_pet_view.gd`의 `prewarm_current_art()`를 등장 전, 성장·의상 변경 시 호출한다. 클릭 윤곽도 함께 준비한다. Main은 종 변경 시 이전 종의 큰 행동 이미지 캐시를 해제한다.
- 이동 중 BORDERLESS 스타일·창 영역을 재설정하지 않는다. 같은 창 순서의 반복 적용도 금지한다. 입력 통과 여부는 별도로 바꾼다.
- 부엉이 성체 수면과 토끼 양 단계·다람쥐 성체 휴식을 원본의 연결된 완성 전신 단위로 복구했다. 원본의 요청 격자와 실제 배치를 반드시 비교한다. 재생성과 패키징 사이에 `repair_complete_cels.cjs --v3 --apply`, 이어 `--v3` 검사에서 잘림 징후 0을 확인한다.
- 꾸미기 메뉴에는 옷 입히기와 옷 색상이 반드시 포함되어야 한다. 보조 의상은 `outfit_mask.gdshader`로 현재 전신 윤곽과 얼굴 보호 영역에 맞춘다. 의상이 없는 걷기 행동은 기본 32프레임을 사용한다.
- 전체 원화가 완성됐다고 잘못 인계하지 않는다. 토끼 외 다른 종의 모든 행동·색에는 아직 완성 착의 원화가 있는 것이 아니며, 보조 의상으로 표시하는 구간이 있다. 해당 원화 제작 상태는 체크리스트의 남은 항목을 따른다.
- 자동 검사: 71,168개 자세 오류 0, 걷기 1,024셀·48이동 검사 통과, 3초 경계 64회 통과. 자동 검사만으로 눈·몸 원본 잘림이나 의상 외형이 승인되지는 않는다.
