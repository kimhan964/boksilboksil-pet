# 토끼의 실제 이동·도토리 오뚝이 잘림 수정

## 토끼

사용자 제보: 깡총 애니메이션만 보이고 실제로 이동하는 것 같지 않음.

- 조사 시 기존 버전도 소품 목적지에는 도착했지만, 한 번에 약 12px만 이동했다. 화면에서 세 번만 뛰고 반대로 도는 점검 방식은 약 37px 왕복이었다.
- 수평 전진 거리를 약 24px/회로 늘렸다. 이전 1.5배로 조정한 애니메이션 주기(1초), 낮은 점프 높이, 60개 원화 프레임은 유지한다. 이 토끼의 전진 거리 조정은 앞선 문서의 ‘보폭 유지’에서 추가 변경된 사항이다. 다른 종의 보폭은 변경하지 않았다.
- `rabbit_hop_motion.gd.stride_length()`를 실제 이동과 점검판이 함께 사용한다. 전체 동물 점검판의 토끼 왕복은 최소 160px로 늘렸다.
- 취소 직후 바로 새 이동을 시작할 때 이전 hop의 origin/destination이 남아 반대 방향으로 전진하는 오류를 재현했다. `cancel_play()`에서 토끼 점프 상태도 초기화한다.
- 마우스 따라오기 종료에서도 진행 중인 토끼의 착지를 마친 후 다음 행동으로 전환한다.

### 검증

- `rabbit_desktop_travel_test.gd`: 수정 전 취소 후 잘못된 방향 전진을 재현. 수정 후 새끼/성체×30/60/144Hz, 좌우 이동 및 중단/재방문 18건 통과.
- `rabbit_hop_test.gd`: 이륙 전/착지 후 수평 미끄러짐 없음, 착지 회복 완료 검사 통과.
- `travel_rate_test.gd`: 전 동물 96건 주기 검사 통과. 토끼의 의도된 수평 거리 변경을 반영함.
- 실제 D3D12 게임 창의 새끼/성체×좌/우 4경로 모두 160px 완료. 약 6.82~7.24초, 화면상의 기준점과 이동 좌표 최대 차이 0.000062px 미만, 역방향 이동 0.
- 이번 캡처는 토끼를 따라가는 크롭이 아닌 **고정된 바탕화면 구간**에서 시작/중간/종료를 비교했다. 결과: `rabbit-world-review-2026-10-05/report.json`, `desktop-displacement.jpg`.
- 첫 검수는 process_frame 신호 직후의 아직 갱신되지 않은 화면 위치를 읽는 문제와 중단된 렌더 대기가 있어 실패했다. 프레임 렌더 완료 후 읽도록 검수기를 고치고 전체 4경로를 다시 실행하여 통과한 결과만 최종 기록으로 사용했다.

## 도토리 오뚝이

사용자 제보: 그림이 이상하게 잘림.

- 원본 PNG에는 잎/몸통/밑부분이 모두 있다. 잘림 원인은 창의 `mouse_passthrough_polygon`이 정면 윤곽에 고정된 반면 그림은 ±0.19 rad 회전했기 때문이다. Windows에서는 이 영역이 네이티브 표시 영역에도 적용된다.
- 전체 흔들림 각도의 윤곽과 2px 여백, 기존 착지 효과 범위를 합친 고정 영역을 사용한다. 흔들리는 동안 매 프레임 네이티브 영역을 바꾸지 않는다. PNG를 잘라내거나 새로 생성하지 않았다.
- `acorn_clip_test.gd`: 121각도×41윤곽점=4,961점 검사. 수정 전 2,639점이 영역 밖, 수정 후 0점.
- 실제 Windows 창에서 왼쪽 최대 기울기/정면/오른쪽 최대 기울기를 각각 띄워 잎과 몸통이 잘리지 않는 것을 확인했다. `acorn-native-review-2026-10-05/`에 렌더 기록.

## 배포

일반 설치판 및 `전체동물-움직임점검-v12`에 함께 반영한다. 기존 구매·종별 해금·저장 상태는 변경하지 않는다. 최종 설치 패키지 검사는 변경 스크립트 13개의 소스 바이트 일치 여부를 확인한다.
